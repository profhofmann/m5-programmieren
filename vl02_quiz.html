Teil A

VL02 · Datentypen, Operatoren, Ausdrücke

Programme = Daten + Algorithmen. Heute die Daten: Werte, Typen, Variablen, Operatoren, Ausdrücke – in Python.

1Kernbegriffe (Flip-Cards)

Erst die Frage auf der Vorderseite beantworten, dann durch Klick wenden.

Was ist ein Ausdruck (expression)?

↻ KLICKEN

Eine Kombination aus Operanden (Konstanten, Variablen, Funktionsaufrufe, Teilausdrücke) und Operatoren. Ein Ausdruck liefert immer einen Wert, z. B. 3.5 * x - 2 / (4 + y). Eine Anweisung dagegen tut etwas (x = 5, print(x)).

Variable, Wert, Typ – wie hängen sie zusammen?

↻ KLICKEN

Eine Variable ist ein benannter Platzhalter für einen Wert. Python ermittelt den Typ aus dem Wert, nicht aus einer Deklaration (dynamisch typisiert). type(12) → int, type(3.25) → float, type("EG") → str, type(True) → bool.

Was legt ein Datentyp fest?

↻ KLICKEN

Wie Werte im Speicher dargestellt werden, welche Operationen erlaubt sind und welche Standardwerte gelten. Dieselben Bits können Zahl, Zeichen oder Wahrheitswert sein – deshalb ist + bei Zahlen eine Addition, bei Zeichenketten eine Verkettung.

/, // und % – was ist der Unterschied?

↻ KLICKEN

/ liefert immer float (7 / 2 → 3.5). // ist die ganzzahlige Division, abgerundet (7 // 2 → 3, -7 // 2 → -4). % liefert den Rest (7 % 2 → 1). Zusammenhang: (a // b) * b + a % b == a.

Rangfolge: Was wird zuerst ausgewertet?

↻ KLICKEN

Klammern → Potenz ** (von rechts) → Vorzeichen → Punktrechnung * / // % → Strichrechnung → Vergleiche → not → and → or. Deshalb -2 ** 2 = -4 und 2 ** 3 ** 2 = 512. Im Zweifel: Klammern setzen.

Woran erkennt Python einen Block?

↻ KLICKEN

An der Einrückung. Der Doppelpunkt eröffnet den Block, alle folgenden gleich eingerückten Zeilen (üblich: 4 Leerzeichen) gehören dazu. Was nicht eingerückt ist, liegt außerhalb. Java und C verwenden dafür { }. Einrückung ist Syntax, nicht Kosmetik.

2Deep Dives

Deep Dive 1: Stelligkeit und Stellung von Operatoren
StelligkeitOperandenBeispiele
einstellig (unär)1-a, +a, not traegt
zweistellig (binär)2a + b, a < b, a and b
dreistellig (ternär)3groesser = a if a > b else b (Java/C: (a > b) ? a : b)
  • Präfix: Operator vor dem Operanden – -a, not fertig, auch Funktionsaufrufe abs(x).
  • Infix: Operator zwischen den Operanden – a + b, der Normalfall.
  • Postfix: Operator nach dem Operanden – n++ in Java/C. In Python nicht vorhanden: n += 1.
Deep Dive 2: Warum 4.35 % 0.6 nicht 0.15 ergibt

Gleitkommazahlen werden binär gespeichert und sind nicht exakt. 4.35 % 0.6 liefert 0.1499999999999998, und 0.1 + 0.2 == 0.3 ist False.

  • Für Stückzahlen und Reste: ganze Zahlen in der kleinsten Einheit verwenden – Zentimeter statt Meter, wie im Aufmaß. 435 % 60 → 15, exakt.
  • Reelle Werte nie exakt vergleichen, sondern mit Toleranz (VL04).
  • Wer den falschen Operator wählt, bekommt keine Fehlermeldung, sondern ein falsches Ergebnis ohne Warnung.
Deep Dive 3: Zuweisung, Vergleich, logische Verknüpfung
  • = ist ein Befehl: rechts berechnen, links speichern. In Python eine Anweisung, kein Ausdruck – y = (x = 5) ist ungültig (in Java/C erlaubt).
  • == ist ein Vergleich und liefert True oder False. Die Verwechslung ist der häufigste Anfängerfehler.
  • Kombinierte Zuweisung: x += 3 entspricht x = x + 3; ebenso -=, *=, /=, //=, %=, **=.
  • Logische Operatoren heißen in Python and, or, not (Java/C: &&, ||, !).
  • Kurzschluss: Bei a and b wird b nicht mehr ausgewertet, wenn a schon False ist – spart Rechenzeit und vermeidet z. B. eine Division durch null.
  • Verkettete Vergleiche sind erlaubt: 0 < x <= 10.
Deep Dive 4: Variablennamen – Regeln und Konventionen

Regeln (Python erzwingt sie): Buchstaben, Ziffern, Unterstrich; nicht mit Ziffer beginnen (1stock ungültig); Groß-/Kleinschreibung wird unterschieden (last ≠ Last); Schlüsselwörter sind tabu (if, for, while, class, def, True …).

Konventionen (PEP 8): snake_case für Variablen (raum_laenge_m), GROSSBUCHSTABEN für Konstanten (G_ERDBESCHL = 9.81), Name nennt Inhalt und Einheit. Umlaute sind technisch erlaubt, aber unüblich.

7 / 2 – / liefert immer eine Gleitkommazahl, auch bei zwei ganzen Zahlen.
7 // 2 – ganzzahlige Division, abgerundet.
7 % 2 – Rest der ganzzahligen Division: 3 · 2 + 1 = 7.
-7 // 2 – // rundet immer ab, also Richtung minus unendlich: −3,5 → −4 (nicht −3).
-2 ** 2 – Potenz vor Vorzeichen: erst 2² = 4, dann negiert. Für +4: (-2) ** 2.
2 + 3 * 4 – Punkt vor Strich; (2 + 3) * 4 wäre 20.
10 / 4 * 2 – gleiche Rangstufe, von links nach rechts: 2.5 · 2. Ergebnis ist float, daher 5.0, nicht 5.
2 ** 3 ** 2 – Potenz wird von rechts ausgewertet: 2 ** 9.
"3" + "4" – + bei Zeichenketten verkettet; Python zeigt Zeichenketten in Anführungszeichen an.
3 > 2 and 2 > 3 – and ist nur wahr, wenn beide Operanden wahr sind. Großschreibung beachten.
0.1 + 0.2 == 0.3 – Gleitkommazahlen sind binär nicht exakt darstellbar; 0.1 + 0.2 ergibt 0.30000000000000004.
type(7 / 7) – / liefert float, auch wenn das Ergebnis „glatt“ ist (1.0).

4Fallstudien und Reflexion

Erst die eigene Antwort notieren, dann die Lösung aufdecken. Die Notiz bleibt stehen, damit Sie vergleichen können.

Fallbeispiel A: Plattenverlegung in Metern

Eine Studentin berechnet für einen 4,35 m langen Flur mit 60 cm breiten Platten die Anzahl der ganzen Platten und die Breite des Passstücks:

flur_m = 4.35
platte_m = 0.6
ganze = flur_m // platte_m      # 7.0
pass_m = flur_m % platte_m      # 0.1499999999999998

Die Anzahl stimmt, das Passstück nicht. Erklären Sie die Ursache und schlagen Sie eine robuste Lösung vor.

Lösung:
  1. Ursache: 4.35 und 0.6 sind Gleitkommazahlen und binär nicht exakt darstellbar. Rest- und Vergleichsoperationen auf float liefern deshalb Rundungsfehler – hier 0.1499999… statt 0.15.
  2. Lösung: In der kleinsten ganzzahligen Einheit rechnen, wie im Aufmaß: flur_cm = 435, platte_cm = 60, 435 // 60 → 7, 435 % 60 → 15. Beide Ergebnisse sind exakt und vom Typ int.
  3. Merkregel: Stückzahlen und Reste → ganze Zahlen und //, %. Längen, Lasten, Flächen → float und /. Nie exakt auf Gleichheit vergleichen.

Fallbeispiel B: Code-Review eines KI-Vorschlags

Ein Sprachmodell liefert auf die Frage „Zähle die Stützen hoch und prüfe die Spannweite“ folgenden Python-Code. Finden Sie alle Stellen, an denen der Code nicht Python ist oder nicht das tut, was er soll:

stuetzen = 12
stuetzen++
spannweite_m = 6.5
if spannweite_m = 6:
    print("Unterzug nötig")
nachweis = last_kn <= n_cr_kn && schlankheit <= 200
Lösung – vier Befunde:
  1. stuetzen++: Postfix-Inkrement existiert in Python nicht (Java/C-Syntax) → SyntaxError. Richtig: stuetzen += 1.
  2. if spannweite_m = 6:: = ist die Zuweisung, in einer Bedingung ist ein Vergleich nötig → SyntaxError. Richtig: ==; fachlich wohl > gemeint („Spannweite über 6 m braucht Unterzug“).
  3. &&: logisches Und heißt in Python and.
  4. last_kn, n_cr_kn, schlankheit sind nirgends zugewiesen → NameError zur Laufzeit.

Regel für dieses Modul: Jede KI-Antwort mit Code wird im Interpreter ausgeführt, bevor sie als richtig gilt. Wer ++ oder && sieht, weiß, dass der Code nicht aus Python stammt.

Fallbeispiel C: Mengenermittlung Beton

Welchen Wert gibt das Programm aus, und welchen Typ hat beton_m3 am Ende? Begründen Sie Zeile für Zeile.

beton_m3 = 0.0
beton_m3 += 12.5     # Bodenplatte
beton_m3 += 8        # Streifenfundamente
beton_m3 *= 1.05     # 5 % Verschnitt
print(beton_m3)
Lösung: Ausgabe 21.525000000000002, Typ float.
  • 0.0 legt den Typ float fest. += 12.5 → 12.5. += 8: int und float lassen sich mischen, Ergebnis bleibt float → 20.5. *= 1.05 → rechnerisch 21.525.
  • Der Interpreter zeigt aber 21.525000000000002: 1.05 ist binär nicht exakt darstellbar (siehe Deep Dive 2). Wer 21.525 erwartet hat, hat richtig gerechnet – und sieht hier, warum Gleitkommazahlen nie exakt verglichen und für die Ausgabe gerundet werden (round(beton_m3, 3), VL04).
  • Hätte die erste Zeile beton_m3 = 0 gelautet, wäre der Typ nach += 12.5 trotzdem float – der Typ hängt am Wert, nicht am Namen.

5Lückentext – Active Recall

Begriff im Vorrat anklicken, dann die passende Lücke anklicken. Ein Klick auf eine gefüllte Lücke gibt den Begriff zurück.

In Python liefert der Operator / immer eine Gleitkommazahl, // die abgerundete ganzzahlige Division und % den Rest. Jeder Vergleich ist ein Ausdruck vom Typ bool. Die Zuweisung = speichert einen Wert, der Vergleich == prüft auf Gleichheit. Zusammengehörige Anweisungen bilden einen Block durch Einrückung. Das Inkrement ++ gibt es in Python nicht; man schreibt += 1.
Python ist dynamisch typisiert: Der Typ hängt am Wert, nicht am Namen. 1 + "2" löst einen TypeError aus, "1" + "2" ergibt "12". Die Potenz ** wird vor dem Vorzeichen ausgewertet, deshalb ist -2 ** 2 gleich -4. Konstanten schreibt man nach PEP 8 in GROSSBUCHSTABEN, Variablen in snake_case.

TypabhängigkeitWas passiert bei 1 + "2"?

  • Ergebnis 3 – Python wandelt automatisch um.
  • Ergebnis '12' – die Zahl wird zur Zeichenkette.
  • Ein TypeError – Zahl und Zeichenkette lassen sich nicht addieren.
  • Ergebnis 12 – die Zeichenkette wird zur Zahl.
Python rät nicht. Erst umwandeln, dann rechnen: 1 + int("2") → 3. Wichtig bei jeder Eingabe, denn input() liefert immer eine Zeichenkette.

RangfolgeWelchen Wert hat 7 // 2 * 2 + 7 % 2?

  • 6
  • 7
  • 8
  • 3.5
Punktrechnung von links nach rechts: 7 // 2 = 3, 3 * 2 = 6, 7 % 2 = 1, dann 6 + 1 = 7. Das ist die Identität (a // b) * b + a % b == a.

ZuweisungWarum ist y = (x = 5) in Python ungültig?

  • Weil Klammern in Zuweisungen verboten sind.
  • Weil die Zuweisung in Python eine Anweisung und kein Ausdruck ist – sie liefert keinen Wert.
  • Weil x vorher nicht deklariert wurde.
  • Die Zeile ist gültig und weist beiden Variablen 5 zu.
In Java und C ist die Zuweisung ein Ausdruck mit Wert, deshalb geht dort y = (x = 5). In Python schreibt man x = y = 5 oder zwei Zeilen.

StelligkeitWelcher Ausdruck enthält einen dreistelligen (ternären) Operator?

  • not traegt
  • a + b + c
  • groesser = a if a > b else b
  • abs(x)
Der bedingte Ausdruck … if … else … hat drei Operanden. a + b + c sind zwei binäre Operatoren hintereinander, not ist unär, abs() ein Funktionsaufruf in Präfix-Schreibweise.

Logische OperatorenWas bedeutet „Kurzschluss“ bei a and b?

  • Das Programm bricht mit einem Fehler ab, wenn a False ist.
  • Ist a bereits False, wird b gar nicht mehr ausgewertet.
  • Beide Operanden werden immer ausgewertet, aber das Ergebnis wird zwischengespeichert.
  • and wird zu or, wenn a False ist.
Das Ergebnis steht bei a == False schon fest. Das spart Rechenzeit und vermeidet Fehler, z. B. n != 0 and summe / n > 10 – die Division wird bei n = 0 nie ausgeführt.

VergleichWas gibt dieses Programm aus?

spannweite_m = 6.5
braucht_unterzug = spannweite_m > 6
print(braucht_unterzug)
  • 6.5
  • 1
  • True
  • Einen SyntaxError, weil in einer Zuweisung kein Vergleich stehen darf.
Ein Vergleich ist ein Ausdruck vom Typ bool und darf überall stehen, wo ein Wert erwartet wird – auch rechts von =. Das ist die Grundlage jeder Verzweigung.

Anweisung und BlockWelche Aussage zu Blöcken in Python ist richtig?

  • Blöcke werden durch geschweifte Klammern { } begrenzt.
  • Jede Anweisung muss mit einem Semikolon enden.
  • Ein Doppelpunkt eröffnet den Block, die Zugehörigkeit ergibt sich aus der Einrückung.
  • Tabulatoren und Leerzeichen dürfen beliebig gemischt werden.
Einrückung ist Syntax. Java/C nutzen { } und Semikolons; Python nicht. Tab und Leerzeichen nicht mischen – das führt zu Fehlern.

Teil B

VL02.1 · Verzweigungen und Schleifen mit Karel

Sequenz, Verzweigung, Wiederholung: Mit diesen drei Kontrollstrukturen lässt sich jeder Algorithmus beschreiben. In Karel ist jede Entscheidung in der Welt sichtbar.

1Kernbegriffe (Flip-Cards)

Was ist eine Bedingung in Karel?

↻ KLICKEN

Ein Ausdruck vom Typ boolean – liefert immer true oder false. Karel kennt fünf Sensoren: onBeeper(), beeperAhead(), frontIsClear(), leftIsClear(), rightIsClear(). Kombiniert mit !, &&, || (Python: not, and, or).

if – wann, und was passiert sonst?

↻ KLICKEN

Einseitige Verzweigung: Der Block wird nur ausgeführt, wenn die Bedingung zutrifft, sonst übersprungen. Typischer Einsatz: eine Aktion absichern, die nur unter einer Voraussetzung erlaubt ist – pickBeeper() auf einem leeren Feld bricht mit Fehler ab.

if-else und else if – worin liegt der Unterschied?

↻ KLICKEN

if-else: zwei Wege, Karel geht immer genau einen – nie keinen, nie beide. else if: mehrere Bedingungen werden von oben nach unten geprüft, die erste zutreffende gewinnt, die weiteren werden nicht mehr geprüft. In Python: elif.

while – wann wird die Bedingung geprüft?

↻ KLICKEN

Vor jedem Durchlauf. Ist sie beim ersten Prüfen schon false, läuft der Block kein einziges Mal. Einsatz, wenn die Anzahl der Wiederholungen vorher unbekannt ist: while (frontIsClear()) { moveForward(); } funktioniert für 3 und für 30 Felder.

repeat oder while?

↻ KLICKEN

repeat (n): Die Anzahl steht vorher fest – repeat (4) { turnLeft(); } ist eine volle Drehung. while: Die Anzahl hängt von der Situation in der Welt ab. Kontrollfrage bei jeder while-Schleife: Was im Block bringt Karel dem Ende näher?

Was ist das Zaunpfahl-Problem?

↻ KLICKEN

Ein Zaun mit 5 Feldern hat 6 Pfähle: Es gibt eine Prüfung mehr als Bewegungen. while (frontIsClear()) prüft jedes Feld und geht weiter – das letzte Feld vor der Wand wird in der Schleife nie geprüft. Lösung: ein zusätzliches if nach der Schleife. Erstes und letztes Feld immer gezielt durchspielen.

Deep Dive 2: Zwei if statt if-else – warum das schiefgeht 
// FALSCH
if (onBeeper()) { pickBeeper(); }
if (!onBeeper()) { dropBeeper(); }

// RICHTIG
if (onBeeper()) { pickBeeper(); } else { dropBeeper(); }
  • Zwei getrennte if sind zwei unabhängige Prüfungen. Die zweite sieht den bereits veränderten Zustand: Beeper da → erstes if hebt ihn auf → Feld leer → zweites if legt ihn wieder ab. Ergebnis: nichts hat sich verändert.
  • if-else prüft die Bedingung genau einmal und entscheidet endgültig.
  • Merksatz: Schließen sich zwei Fälle gegenseitig aus, gehört else dazu – kein zweites if.
Deep Dive 3: Rechte-Hand-Regel und Reihenfolge der Bedingungen 
if (rightIsClear()) {
    turnRight();
    moveForward();
} else if (frontIsClear()) {
    moveForward();
} else if (leftIsClear()) {
    turnLeft();
    moveForward();
} else {

}
  • Wer im Labyrinth immer die rechte Hand an der Wand lässt, findet aus jedem einfach zusammenhängenden Labyrinth hinaus.
  • Sind rechts und vorne frei, wird nur der erste Fall ausgeführt. Die Reihenfolge ist Programmlogik: Steht frontIsClear() oben, nimmt Karel einen anderen Weg.
  • Das abschließende else fängt den Rest ab – hier die Sackgasse.

3Schreibtischtest – was macht Karel?

Spielen Sie den Code von Hand durch. Karel steht auf Feld 1, blickt nach Osten, am Ende der Reihe ist eine Wand. B = Beeper liegt, _ = leer.

Schreibtischtest 1Reihe mit 5 Feldern: B _ B _ B. Wie sieht die Reihe nach dem Lauf aus?

while (frontIsClear()) {
    if (onBeeper()) {
        pickBeeper();
    }
    moveForward();
}
  • _ _ _ _ _ – alle Beeper sind aufgehoben.
  • _ _ _ _ B – der Beeper auf dem letzten Feld bleibt liegen.
  • B _ B _ B – nichts verändert sich.
  • _ _ B _ B – die Schleife bricht nach zwei Durchläufen ab.
Zaunpfahl-Problem: Die Schleife läuft viermal (prüfen, Schritt). Auf Feld 5 steht Karel vor der Wand, frontIsClear() ist false, das Feld wird in der Schleife nie geprüft. Lösung: if (onBeeper()) { pickBeeper(); } nach der Schleife.

Schreibtischtest 2Reihe mit 4 Feldern: _ B _ _. Wie sieht die Reihe nach fillGaps() aus?

void fillGaps() {
    while (frontIsClear()) {
        moveForward();
        if (!onBeeper()) {
            dropBeeper();
        }
    }
}
  • B B B B – alle Lücken sind geschlossen.
  • _ B B B – Feld 1 bleibt leer.
  • B B B _ – Feld 4 bleibt leer.
  • _ B _ _ – nichts verändert sich.
Erst Schritt, dann Prüfung: Karel verlässt Feld 1, ohne es anzusehen. Felder 2 bis 4 werden nach dem jeweiligen Schritt geprüft – auch das letzte, weil der Schritt dorthin noch in der Schleife liegt. Reihenfolge im Block ist Programmlogik: Prüfung vor dem Schritt plus ein if nach der Schleife (Musterlösung), oder Schritt vor der Prüfung plus ein if vor der Schleife.

Schreibtischtest 3Karel steht auf einem Feld mit Beeper. Was passiert?

while (onBeeper()) {
    turnLeft();
}
moveForward();
  • Karel dreht sich einmal nach links und geht dann weiter.
  • Karel dreht sich viermal, steht wieder in Ausgangsrichtung und geht weiter.
  • Karel dreht sich endlos – das Programm endet nie.
  • Das Programm bricht mit einem Fehler ab, weil der Beeper nicht aufgehoben wird.
Endlosschleife: Drehen ändert nichts daran, ob ein Beeper auf dem Feld liegt. Die Bedingung bleibt true. Kontrollfrage vor jeder Schleife: Was im Block bringt Karel dem Ende näher? Hier: nichts.

4Fallstudien und Reflexion

Fallbeispiel D: Reihenfolge in der Rechte-Hand-Regel

Eine Studentin schreibt die Rechte-Hand-Regel um und setzt frontIsClear() an die erste Stelle, weil Karel „ja meistens geradeaus geht“:

if (frontIsClear()) {
    moveForward();
} else if (rightIsClear()) {
    turnRight(); moveForward();
} else if (leftIsClear()) {
    turnLeft(); moveForward();
} else {
    turnAround();
}

Karel steht in einem Gang, rechts geht ein Abzweig ab, geradeaus ist frei. Was passiert jetzt im Vergleich zur Originalversion, und ist das Programm noch eine Rechte-Hand-Regel?

Lösung:
  1. Bei else if gewinnt die erste zutreffende Bedingung. Da vorne frei ist, geht Karel geradeaus und ignoriert den rechten Abzweig. Die Originalversion wäre rechts abgebogen.
  2. Das Programm ist damit keine Rechte-Hand-Regel mehr, sondern „geradeaus, solange möglich“. Die Garantie, aus einem einfach zusammenhängenden Labyrinth herauszufinden, gilt nicht mehr – Karel kann in Zyklen laufen.
  3. Merksatz: Die Reihenfolge der Bedingungen ist Programmlogik, nicht Stil. Jede Umsortierung ist eine Änderung des Algorithmus.

Fallbeispiel E: Vom Feld-Invertieren zur Reihe

Gegeben ist das Programm aus VL02.1, das ein einzelnes Feld invertiert (Beeper weg, wenn einer da ist, sonst einen hinlegen). Erweitern Sie es so, dass jedes Feld einer Reihe unbekannter Länge invertiert wird. Notieren Sie Ihren Code und prüfen Sie ihn für die Reihen B _ B und _ _ _ _.

if (onBeeper()) {
    pickBeeper();
} else {
    dropBeeper();
}
Musterlösung: 
void invertRow() {
    while (frontIsClear()) {
        if (onBeeper()) {
            pickBeeper();
        } else {
            dropBeeper();
        }
        moveForward();
    }
    if (onBeeper()) {      // letztes Feld
        pickBeeper();
    } else {
        dropBeeper();
    }
}
  • B _ B → _ B _; _ _ _ _ → B B B B.
  • Bewertungskriterien: while statt fester Schrittfolge (Länge unbekannt); if-else statt zwei if (Fälle schließen sich aus); letztes Feld behandelt (Zaunpfahl); keine überflüssigen Anweisungen.
  • Typische Fehler: zwei if hintereinander (Feld bleibt unverändert), letztes Feld vergessen, erst Schritt dann Prüfung (Feld 1 bleibt unverändert).

5Lückentext – Active Recall

Eine Bedingung ist ein Ausdruck vom Typ boolean. if prüft genau einmal und führt den Block höchstens einmal aus; while prüft vor jedem Durchlauf. Schließen sich zwei Fälle gegenseitig aus, gehört else dazu – kein zweites if. Steht die Anzahl der Wiederholungen vorher fest, ist repeat die richtige Wahl. Dass das letzte Feld vor der Wand in der Schleife nie geprüft wird, heißt Zaunpfahl-Problem. Bei else if gewinnt die erste zutreffende Bedingung. In Python heißt else if elif.

6Quick-Check VL02.1

if vs. if-elseWann verwenden Sie if ohne else?

  • Wenn zwei sich ausschließende Wege möglich sind.
  • Wenn nur in einem Fall etwas zu tun ist und sonst nichts.
  • Wenn die Bedingung immer wahr ist.
  • Wenn die Anzahl der Durchläufe vorher feststeht.
Einseitige Verzweigung: Block ausführen oder überspringen. Gibt es zwei sich ausschließende Wege, gehört else dazu.

else ifBei einer else if-Kette treffen zwei Bedingungen gleichzeitig zu. Was passiert?

  • Beide Blöcke werden ausgeführt.
  • Das Programm bricht mit einem Fehler ab.
  • Nur der Block der ersten zutreffenden Bedingung wird ausgeführt; die weiteren werden nicht mehr geprüft.
  • Der Block der letzten zutreffenden Bedingung wird ausgeführt.
Bedingungen werden von oben nach unten geprüft – die erste zutreffende gewinnt. Deshalb ist die Reihenfolge Programmlogik.

if vs. whileWorin unterscheiden sich if (frontIsClear()) { moveForward(); } und while (frontIsClear()) { moveForward(); }?

  • Gar nicht – beide bewegen Karel bis zur Wand.
  • if macht höchstens einen Schritt, while geht bis zur Wand – egal wie breit die Welt ist.
  • if prüft vor jedem Schritt, while nur einmal.
  • while macht genau einen Schritt mehr als if.
if prüft einmal und führt höchstens einmal aus. while prüft vor jedem Durchlauf und wiederholt, solange die Bedingung gilt.

whileDie Bedingung einer while-Schleife ist schon beim ersten Prüfen false. Wie oft läuft der Block?

  • Genau einmal – der erste Durchlauf findet immer statt.
  • Kein einziges Mal.
  • Endlos.
  • Das hängt vom Inhalt des Blocks ab.
Die Prüfung findet vor jedem Durchlauf statt, auch vor dem ersten. Reihe B in der Übung testet genau das: Prüfung vor dem ersten Schritt.

repeat vs. whileWelche Aufgabe löst man sinnvoll mit repeat statt mit while?

  • Bis zur nächsten Wand laufen.
  • Alle Beeper einer Reihe unbekannter Länge aufheben.
  • Eine volle Drehung um 360° ausführen.
  • Durch ein Labyrinth zum Ausgang finden.
repeat (4) { turnLeft(); } – die Anzahl steht vorher fest. Bei allen anderen Aufgaben hängt die Anzahl von der Welt ab → while.

Bedingungen kombinierenWelche Bedingung bedeutet „vor mir ist keine Wand und auf dem Feld vor mir liegt kein Beeper“?

  • frontIsClear() || !beeperAhead()
  • !frontIsClear() && beeperAhead()
  • frontIsClear() && !beeperAhead()
  • frontIsClear() and not beeperAhead()
&& ist das logische Und, ! die Verneinung. Die letzte Option ist inhaltlich richtig, aber Python-Syntax – in Karel (Java) ein Syntaxfehler.

FehlerbildWarum sind zwei if hintereinander hier ein Fehler?

if (onBeeper()) { pickBeeper(); }
if (!onBeeper()) { dropBeeper(); }
  • Weil Karel nicht zwei Bedingungen hintereinander prüfen kann.
  • Weil das zweite if den Zustand nach dem ersten sieht – beide Blöcke werden ausgeführt und heben sich auf.
  • Weil !onBeeper() keine gültige Bedingung ist.
  • Es ist kein Fehler – das Programm invertiert das Feld korrekt.
Beeper da → aufheben → Feld leer → wieder ablegen. Ergebnis: unverändert. if-else prüft einmal und entscheidet endgültig.

Karel → PythonWie lautet else if (frontIsClear()) { moveForward(); } in Python?

  • else if frontIsClear(): moveForward()
  • elif frontIsClear(): und darunter eingerückt moveForward()
  • elseif (frontIsClear()) { moveForward() }
  • else: if (frontIsClear()) moveForward();
Python: elif, Doppelpunkt, Block durch Einrückung, keine runden Klammern um die Bedingung nötig und keine geschweiften Klammern.
